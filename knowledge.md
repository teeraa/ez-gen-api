## Architecture Decisions

### AD-001: UUID Primary Keys
All user-facing entity IDs are UUID v4, generated by the application (or PostgreSQL
`gen_random_uuid()`). Provider task IDs (BytePlus) are stored internally and never
exposed in API responses.

**Rationale:** Prevents enumeration attacks; application controls identity.

### AD-002: No AutoMigrate in Production
Schema migrations are written as SQL files in `migrations/` and run explicitly.
GORM's `AutoMigrate` is prohibited in production startup code.

**Rationale:** Explicit migrations are auditable and reversible. AutoMigrate can
cause silent destructive changes.

### AD-003: Provider Isolation
BytePlus-specific types (`apps/services/modelark/`) must not leak into facade or
handler layers. The facade receives application-domain types only.

**Rationale:** Enables future provider changes without modifying business logic.

### AD-004: Media URL Persistence
BytePlus output URLs are ephemeral. When a job succeeds, the output must be
immediately downloaded and stored in application object storage. The stored
object's key (not the BytePlus URL) is what gets persisted to the database.

**Rationale:** Provider URLs expire; application must own its media.

## BytePlus ModelArk

> See `docs/engineering/modelark-integration-research.md` for full research.

- API key env var: `ARK_API_KEY` (SDK convention) — never log, never expose
- Base URL: `https://ark.ap-southeast.bytepluses.com/api/v3`
- Official Go SDK: `github.com/volcengine/ark-runtime-go`
- Video generation is asynchronous — create task, then poll for status
- Provider status values: `queued`, `running`, `succeeded`, `failed`, `cancelled`
- Output URL lifetime: ~24 hours — download immediately on `succeeded`
- Task ID field in create response: `id` (prefix: `cgt-...`)

## Job Status Values

Application statuses (see `video-data-model-proposal.md` for full state machine):

| Status | Description |
|---|---|
| `queued` | Job persisted, not yet sent to BytePlus |
| `submitted` | BytePlus task created, awaiting first status |
| `processing` | BytePlus is generating |
| `succeeded` | Generation complete; media persisted to storage |
| `failed` | Terminal failure; `failure_code` set |
| `cancelled` | User or system cancelled |
