# Video editor phase 1 API

Authoritative contract for the independent footage editor. Existing generation,
scene and storyboard routes retain their current contracts. All routes below are
under `/open/v1/video-editor`, require the existing JWT bearer middleware, and use
standard `{data,requestId}` success / `{code,message,requestId}` error envelopes.
Browser calls go through the Next proxy `/api/proxy/video-editor`.

## Limits and identity

- Uploaded video: at most 52,428,800 bytes (50 MiB), duration at most 1,200 seconds,
  dimensions at most 4,096 pixels per side. Actual container, tracks and codecs are
  inspected by ffprobe; MP4/MOV and WebM only. A file extension is not validation.
- Uploaded audio uses the same route, multipart fields and limits (50 MiB, 1,200 s).
  ffprobe must find MP3, WAV or M4A (MP4-family container) with at least one audio
  stream (AAC, MP3, ALAC or PCM) and no playable video stream; embedded cover art
  (attached-picture streams) is ignored. The audio stream is fully decoded once at
  upload. Accepted declared types: `audio/mpeg|audio/mp3` for MP3,
  `audio/wav|audio/x-wav|audio/wave|audio/vnd.wave` for WAV,
  `audio/mp4|audio/x-m4a|audio/m4a|audio/aac|video/mp4|video/quicktime` for M4A, or
  `application/octet-stream`; a declared type contradicting the inspected container
  is `INVALID_FILE_TYPE`. An MP4 holding only audio becomes an audio asset.
- Up to 100 source assets per project; at most two processing uploads per user.
  The handler also bounds simultaneous per-user multipart parsing/processing.
- Both save and export accept at most 20 segments and 1,200 seconds total.
- Every ID is an application UUID. Every segment has its own unique `id` and an
  owned ready `assetId`; the same source asset may appear in many segments.
- Segment array order is timeline order. `start`/`end` are source seconds,
  `0 <= start < end <= sourceDuration`. `volume` is finite and between 0 and 1;
  zero is mute. Aspect ratios are `9:16`, `16:9`, `1:1`.
- Source media is immutable once ready. Original filenames are display-only;
  object keys and local paths are generated by the server. No client media URL or
  storage path is accepted.
- Timestamps use UTC RFC3339. Read URLs are signed for one hour and regenerated on
  owned project/assets/download reads; signed URLs are never stored in the DB.

## DTOs

`Segment`: `{id,assetId,start,end,volume}`.

`Asset`:
`{id,projectId,clientUploadId,name,kind,status,duration,width,height,hasAudio,sizeBytes,
previewUrl,frames,expiresAt,failureCode,failureMessage}`. `kind` is `video|audio`
(rows created before migration 024 are `video`). Audio assets have `width=height=0`,
`hasAudio=true`, `frames=[]` and a signed `previewUrl` for playback.
`status` is `processing|ready|failed`. `previewUrl` and `expiresAt` are nullable;
`frames` is an array of `{time,url}`. Ready sources persist at most 24 JPEG samples.
`processing` reservations whose lease expires are returned as failed with
`UPLOAD_INTERRUPTED`, allowing the same original file/clientUploadId to retry.

`Project`: `{id,title,aspectRatio,revision,createdAt,updatedAt,segments,audioClips,
textLayers,assets}`. Initial revision is 1, aspect ratio `9:16`; segments,
audioClips, textLayers and assets are empty arrays. They are always arrays, also
for legacy projects.
Project list uses the same DTO with empty assets (no signing work for a list).

`Export`: `{id,projectId,revision,status,resolution,aspectRatio,duration,createdAt,
updatedAt,failureCode,failureMessage,canRetry}`. Status is
`queued|processing|completed|failed`. `canRetry` is true only for failed exports
with fewer than three claimed attempts. Output keys and attempt tokens are not
public. A retry uses the original immutable snapshot.

## Audio clips and text layers

`AudioClip`: `{id,assetId,at,start,end,volume,originJobId?}`. Up to 20 per project; `id` is a
unique UUID; `assetId` is an owned ready `kind=audio` asset; `at >= 0` is the
timeline position in seconds; `start`/`end` are source seconds with
`0 <= start < end <= sourceDuration`; `volume` is finite 0..1 (0 mutes);
`at + (end - start) <= 1200`. Clips may overlap each other and video audio; all
are mixed at their own volume (no normalisation, no fades).

`TextLayer`: `{id,text,start,end,x,y,fontSize,color,align,scaleX?,scaleY?,originJobId?}`. Up to 50 per project;
`id` is a unique UUID. `start`/`end` are timeline seconds, `0 <= start < end <= 1200`.
`text` is normalised server-side (CRLF/CR become LF, then surrounding whitespace is
trimmed) and must then be nonblank, at most 500 Unicode characters and at most 6
lines, with no control characters other than LF; the normalised text is stored and
returned. `x`,`y` are 0..1 frame fractions of the text box centre anchor; `align`
aligns individual lines inside that box. `fontSize` is an
integer 12..200 in pixels at a 1080-pixel-high reference, scaled to the output
height. `color` is `#RRGGBB`. `align` is `left|center|right`. Optional `scaleX`
and `scaleY` are finite numbers 0.1..5, default 1 when omitted/null. They stretch
the natural text box independently along each axis, including its shadow; the
scaled box retains the centre anchor and clamps inside the frame (top/left wins
for an oversized box). There is no automatic wrapping. Scales persist in project
JSON and immutable export snapshots. Explicit zero is invalid.

Optional `originJobId` on text/audio is a valid UUID identifying AI-generated
tracks; omitted means manually owned. It persists across save/export snapshots.
Automatic AI composition replaces only explicitly marked tracks and preserves
manual tracks; legacy AI jobs retain segment-only behavior. See the AI contract.

Video `segments` must reference `kind=video` assets; audio clips must reference
`kind=audio` assets. Otherwise `VALIDATION_ERROR`. AI jobs
(`video-editor-ai-api-contract.md`) analyse video assets only: any audio asset id in
`assetIds` is `VALIDATION_ERROR`. Applying a legacy/manual-mode AI draft replaces only `segments` and preserves
`audioClips` and `textLayers`; auto-compose additionally merges explicitly
AI-owned generated tracks while preserving unmarked manual tracks.

## Routes

| Method | Path | Input / result |
| --- | --- | --- |
| GET | `/capabilities` | `{available,unavailableReason,maxUploadBytes,maxSegments,maxDuration,aspectRatios,resolutions,maxAudioClips,maxTextLayers,textOverlays,textTransforms,audioFormats}` |
| GET | `/projects?page=1&limit=20` | `{items:Project[],total,page,limit}`, max limit 50 |
| POST | `/projects` | `{requestId,title}` → Project; 201 created, 200 replay |
| GET | `/projects/:id` | Project with ready signed media/frames |
| PUT | `/projects/:id` | `{revision,title,aspectRatio,segments,audioClips?,textLayers?}` → Project with revision + 1 |
| GET | `/projects/:id/assets` | `{items:Asset[]}` |
| POST | `/projects/:id/assets` | Multipart `file`, `clientUploadId` → Asset; 201 processed, 200 replay |
| GET | `/projects/:id/exports` | `{items:Export[]}`, newest first, most recent 100 |
| POST | `/projects/:id/exports` | `{requestId,revision,resolution}` → Export; 202 created, 200 replay |
| GET | `/exports/:id` | Export |
| POST | `/exports/:id/retry` | Existing Export, 202; no duplicate work for active/completed jobs |
| GET | `/exports/:id/download` | `{downloadUrl,expiresAt,filename}`, completed only |

`title` is nonblank, at most 200 Unicode characters. `resolution` is `720p|1080p`.
On PUT, `audioClips`/`textLayers` that are omitted (or `null`) keep the stored value;
a present array (including `[]`) replaces it. Revision semantics are unchanged.

Capabilities: `textTransforms: true` advertises independent text-axis scaling in
save/export. Clients must gate resize for older servers omitting this flag.
`maxAudioClips` is 20, `maxTextLayers` 50, `audioFormats`
`["mp3","wav","m4a"]`. `textOverlays` is true only when the editor is available,
FFmpeg has the `drawtext` filter and the configured `FFMPEG_FONT_FILE` is readable
and contains Thai glyphs (checked through its cmap). It is evaluated once per
process. When false, projects can still store text layers, but exporting a
snapshot that contains any text layer returns 503 `MEDIA_UNAVAILABLE`.
Empty segments may be saved but cannot be exported. Capability availability
requires configured storage and discoverable ffmpeg/ffprobe; an actual operation
can still fail due to invalid media, storage or runtime encoding failure.

## Concurrency, retries and status

Project creation is idempotent per `(user,requestId)`; changed payload returns
`IDEMPOTENCY_CONFLICT`. Saves use atomic revision comparison; stale edits are not
silently overwritten. Export submission stores a snapshot of ordered source keys,
trim/volume, audio clips (with their source keys), text layers, output ratio and
resolution under the requested project revision. Output duration is the sum of the
video segments. Audio clips starting at/after that end are dropped and others are
cut at it; text layers are clipped to `[0,total]` and dropped when `start >= total`.
Replaying the same export request returns the original export even if the project
has since changed. A different payload under that request ID is a conflict.

Uploads hash bounded bytes, then reserve `(user,project,clientUploadId)` before
storage writes. Same hash/ready returns the prior asset. Same key/different file
is a conflict. Active reservation returns `UPLOAD_IN_PROGRESS`; expired/failed
reservation can be reclaimed. Each attempt uses new object keys and an attempt
fence so stale completion cannot overwrite a newer ready asset. Upload processing
has a 120-second deadline; the HTTP read/write limits are 60/150 seconds. Clients
should reconcile ambiguous failures by reading assets, retaining the original
clientUploadId for retries.

The export worker claims one queued row using `FOR UPDATE SKIP LOCKED`. Claims
have attempt tokens and 25-minute leases; renderer work has a 20-minute outer
context and existing FFmpeg's inner 15-minute limit. Output keys include the
attempt token. Stale completion cannot mutate a newer attempt; expired jobs become
failed/retryable with `RENDER_INTERRUPTED`. Successful output is H.264/AAC MP4,
fully decoded before publication, with black aspect-ratio padding and per-segment
volume. Existing renderer callers with nil volume retain their original audio.
Audio clips are trimmed, delayed to `at` (sample-exact) and mixed over segment audio
with `amix normalize=0`, so summed loud sources can clip. Text is burned with
FFmpeg `drawtext` from a temporary text file with expansion disabled.

## Errors

| HTTP | Code | Meaning |
| --- | --- | --- |
| 401 | `UNAUTHORIZED` | Authentication missing/invalid |
| 404 | `NOT_FOUND` | Resource missing or owned by someone else |
| 409 | `REVISION_CONFLICT` | Saved revision has changed |
| 409 | `IDEMPOTENCY_CONFLICT` | Request ID used with different payload/file |
| 409 | `UPLOAD_IN_PROGRESS` | Same upload reservation is still processing |
| 409 | `UPLOAD_LIMIT_REACHED` | Project already has 100 assets |
| 429 | `UPLOAD_BUSY` | Two uploads are already processing for this user |
| 409 | `EXPORT_NOT_READY` | Download/retry not valid in current export state |
| 413 | `FILE_TOO_LARGE` | Input exceeds 50 MiB |
| 422 | `VALIDATION_ERROR` | Invalid timeline/project/export data |
| 422 | `INVALID_FILE_TYPE` | Unsupported container/codec/track or invalid video |
| 503 | `MEDIA_UNAVAILABLE` | Required media runtime unavailable, including text export without drawtext/Thai font |
| 503 | `STORAGE_UNAVAILABLE` | Storage write/sign failed |
| 500 | `INTERNAL_ERROR` | Unexpected failure with no internal detail disclosure |

No SQL, filesystem path, storage credential or provider payload is returned.
Every resource read/sign validates ownership first. Durable failed processing
records expose only sanitized failure codes/messages.

## Deployment and verification

Apply `migrations/021_video_editor.sql` and then
`migrations/024_video_editor_audio_text.sql` (asset `kind`, project `audio_clips` /
`text_layers` JSONB arrays defaulting to `[]`) separately before deploying this
version; the API writes these columns. Configure `FFMPEG_FONT_FILE` with a
Thai-capable font for text export (see `.env.example`); the Docker image currently
installs only `ttf-dejavu`, which has no Thai glyphs.
Production startup never runs migrations. The API uses the existing durable
storage configuration and the existing FFmpeg installation; no AI provider call
is involved. Phase 2 AI planning, music and transcription are not implemented.

The explicit isolated fixture executable is `cmd/video-editor-fixture`: it refuses
any DSN except `127.0.0.1:15457/ai_editor_phase1`, applies schema only there
(021, then 024 when the `kind` column is missing; it reads `FFMPEG_FONT_FILE`), serves
local signed storage at port 18157 and exposes fixed fixture authentication.
It must never be used as the production API. See task evidence for exact tests.

Download responses use `SignedDownloadURL` with the generated `.mp4` filename,
not a normal preview signing request. Storage must honor its signed attachment /
`download` parameter so cross-origin browser links download rather than navigate
the editor away. The existing Supabase adapter and the isolated fixture implement
this contract; tests verify attachment signing is used only for downloads.

### Video editor clip effects (2026-11-03)

Capability `clipEffects: true` (absent on older backends) gates every field below; the web client sends none of them otherwise.

- `Segment.speed?: number` — 0.25..4; absent or 1 = normal. A segment lasts `(end-start)/speed` timeline seconds, and the 1,200 s ceiling counts timeline seconds. Export: `setpts=(PTS-STARTPTS)/speed` and pitch-preserving `atempo` stages, each within 0.5–2.
- `Segment.fadeIn?/fadeOut?: number` — timeline seconds, each 0..10, `fadeIn+fadeOut ≤` segment timeline length. Export fades picture from/to black (`fade`) and the segment's own audio (`afade`); text layers stay visible because they are drawn after the concat.
- `AudioClip.fadeIn?/fadeOut?: number` — seconds of source span, same limits against `end-start`. A clip cut at the video end keeps its fade-in and shrinks its fade-out to fit the remaining part.
- Detached audio: `AudioClip.assetId` may name a ready **video** asset with `hasAudio: true`; the web client mutes the source segment (`volume: 0`) when detaching and allows it only at speed 1.
- Defaults are omitted from stored JSON (`omitempty`), so older projects and readers are unchanged. No migration: segments and audio clips are JSONB.
- Snap while dragging and trimming is client-only (0, playhead, video cuts, other audio/text edges; 8 px reach).

### Video editor looks, transitions, text styles and image layers (2026-11-03)

- Capability `clipStyles: true` gates segment looks, transitions and text styles; the web client never sends them otherwise (older servers would drop them silently).
- Segment look (all optional, flat on the segment): `brightness`/`contrast`/`saturation` −1..1 → FFmpeg `eq` brightness·0.3, contrast 1+c/2, saturation 1+s (−1 = greyscale); `fit: "cover"` fills by cropping (default letterbox); `zoom` 1..3; `panX`/`panY` −1..1 pick the visible part (−1 = left/top). Preview uses an SVG filter with the same formula and the same scale→pad→crop geometry.
- Segment `transition` (`fade`, `fadeblack`, `fadewhite`, `wipeleft`, `wiperight`, `slideleft`, `slideright`, `circleopen`) with `transitionDuration` 0.1..2 s, at most half of this and the previous segment; never on the first. The segment starts that much earlier, so the total is Σ(timeline lengths) − Σ(transitions). Export: `xfade` + `acrossfade` (tri), `concat` where a clip has none; with no transitions the legacy single `concat` is unchanged.
- Text style: `outlineWidth` 0..20 px@1080 with `outlineColor`; `boxOpacity` 0..1 with `boxColor` (box padding = round(0.3·font px) + outline); `animation` `fade` | `slide` (0.3 s or a third of short layers; slide rises 4% of the height). Style is painted outside the measured text box, so clamping is unchanged.
- Image layers (capability `imageLayers: true`, requires **migration 028**): assets of kind `image` (PNG/JPEG/WebP stills ≤ 4096 px, decoded on upload); `Project.imageLayers: {id, assetId, start, end, x, y, width, opacity}[]` max 20 — centre x/y 0..1, width 0.02..1 of the frame width, opacity 0.05..1. Overlaid under text; clipped to the video like text.
- Ripple delete (client only): deleting a video clip shifts later audio/text/image items left by the amount the video got shorter.
