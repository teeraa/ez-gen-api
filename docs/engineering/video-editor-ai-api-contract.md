# Video editor AI: phase 2

This additive domain uses `/open/v1/video-editor` and the same authenticated response envelopes and ownership rules as [phase 1](video-editor-api-contract.md). Production is disabled by default. The implemented provider is Gemini `gemini-3.5-flash-lite`; transcription is local faster-whisper 1.2.1 by default, with an explicitly selected local Typhoon ASR Real-time ONNX CPU option (`EDITOR_ASR_PROVIDER=typhoon`). See [Typhoon setup and timing limits](../../scripts/typhoon/README.md). No provider SDK or paid fallback is used. Missing configuration never generates fixture results.

Capabilities: `{autoCompose:true,instructionEdits,available,unavailableReason,transcriptionAvailable,analysisAvailable,maxAssets:8,maxSourceDuration:600,maxFrames:24,maxTargetDuration:120,maxSegments:20,maxJobsPerDay:20,maxCloudCalls:6,cloudNotice,connectionMode,supportedOptions}`. `connectionMode` is `configured` in production and `fixture` only in the isolated executable. `supportedOptions.removeSilence`, `subtitles` and `music` are true: auto mode composes grounded captions and may use existing owned audio. Filler/shaky remain false. These flags do not advertise voice or music generation. Availability requires the enable flag, installed schema, local ASR dependency/model, configured Gemini key/version, storage and FFmpeg. Default-off project job lists return empty after checking project ownership without accessing the new AI tables. Other AI actions return `AI_UNAVAILABLE` while explicitly disabled. When enabled but cloud keys are missing, existing review/draft/apply/history remain usable without cloud calls.

Job: `{autoCompose,id,projectId,sourceRevision,phase,status,stage,assetIds,brief,targetDuration,style,audioMode,removeSilence,progress:{completedAssets,totalAssets},transcripts,visuals,concepts,selectedConceptId,draft,failureCode,failureMessage,canRetry,retryAt,cloudCallsUsed,cloudCallsLimit,createdAt,updatedAt,appliedRevision}`. Arrays are nonnull. Selection/draft/retryAt/appliedRevision are nullable. Times are UTC RFC3339. Phase is `analysis|planning`; status is `queued|processing|awaiting_concept|review|applied|failed|cancelled`. Stage is `queued|transcribing|visual_analysis|concepts|planning|review|applied|failed|cancelled`. Progress reports actual completed source assets, not a fabricated percentage.

Transcript: `{assetId,language,text,hasSpeech,segments:[{start,end,text,words:[{start,end,text}]}]}`. Silent/non-speech sources have empty text/segments and `hasSpeech:false`. Word tokens may be zero-duration and may be Thai characters rather than lexical words. Typhoon ONNX uses separately decoded PCM contexts split at conservative sustained quiet pauses, with retained contexts bounded to 12 seconds and `words: []`; model emission times are not treated as phonetic word boundaries. For continuous retained audio, boundaries use the quietest measured 50ms interval sampled every 20ms between approximately 8 and 12 seconds. Each actual PCM span is independently transcribed and no samples are dropped at these subdivisions. This yields shorter editorial choices; adjacent contexts and longer runs remain available, and no multiple-cut quota is imposed. A measured energy minimum can still fall within speech. Silence inside these windows is retained. Original context boundaries are preserved when they fit the target; they are not guaranteed sentence or word-aligned cuts. Speech segment durations are positive. This feature does not claim forced-alignment or Thai word-boundary accuracy.

Visual: `{assetId,summary,frames:[{time,description}]}`. Three newly extracted JPEGs per source, maximum 512px; the tiny phase-1 timeline thumbnails are not the analysis evidence. Concept: `{id,title,summary,duration,durationReason?}`, 2–3 concepts with server IDs. Draft: `{revision,duration,durationReason?,textStyles?:{caption?:TextStyle,title?:TextStyle},textLayers?:TextLayer[],audioClips?:AudioClip[],compositionNotes?:string[],segments:[{id,assetId,start,end,volume,speed?,fadeIn?,fadeOut?,transition?,transitionDuration?,brightness?,contrast?,saturation?,fit?,zoom?,panX?,panY?,title,reason,evidenceId}]}` (effect fields: see [AI editing tools](#ai-editing-tools)). Generated segments select only server-issued evidence windows; model output cannot supply arbitrary paths, asset IDs or timestamps. Each concept is an independent complete alternative aiming for the requested target, not a fraction of a shared duration budget. Planning aims for the requested target even if the advisory concept duration is shorter. Evidence no longer has a six-second shot ceiling. Speech sources in both silence modes supply original speech/pause-context units, short two-unit and medium three-unit runs, plus an optional longer continuity fallback within the requested target. Speech evidence is capped at 48 choices across sources and 24 per source; sampled starting boundaries retain choices from later source positions. Half the per-source choice budget is reserved for individual contexts (up to 12 for one source), with remaining capacity offering pairs and longer continuity alternatives. Non-speech choices remain limited to 12 sampled starts plus a tail. Remove-silence mode does not bridge gaps greater than 0.35 seconds; keep mode may retain the original gaps. Coarse Typhoon contexts are not relabeled as sentences. A source context longer than the entire target supplies a clearly marked partial-context fallback bounded by the source; it does not claim word/sentence alignment. Non-speech sources supply target-length continuous choices and a tail choice.  Refined source context descriptions are truncated for prompt size, with full transcript context supplied separately. Original candidate IDs/timestamps remain server-owned. Alternative candidates can overlap, but selected windows must not overlap source footage. Exactly adjacent selected windows from the same asset are merged only when volume, title and reason are identical. Different narrative roles stay separate for review; separate rows over identical continuous footage do not themselves create a visual change. A merged result retains a new server-issued evidence record for the exact verified union. Source visual summaries are supplied once per source to planning. Generated plans may be shorter than the requested target; there is no minimum target percentage. They must remain nonempty, use valid unique evidence IDs and owned source bounds, contain at most 20 segments, and total at most `targetDuration + 0.05` seconds (numeric tolerance) and 1200 seconds. The provider planning schema restricts evidence IDs to the actual server choices and bounds the maximum selection count by the sum of the shortest candidate durations within the target tolerance. This is a safe upper bound, not a required count; final overlap, metadata and duration validation still apply. Planning includes explicit candidate durations. Invalid planning results produce server-only static validation categories without recording transcripts or provider payloads. Preflight validates evidence IDs/source bounds and rejects empty evidence, but never rejects solely because available footage is shorter than the target. No repeated evidence, invented filler, automatic retry or automatic regeneration is added. Legacy unedited review drafts (revision 1) may also be applied when shorter, without a manual save. Historical `AI_INSUFFICIENT_EVIDENCE` and `AI_DURATION_MISMATCH` failures allow the existing explicit user retry subject to normal attempt, provider availability and budget limits; no provider calls run automatically. Applied request replays preserve the existing response. Manual edits retain known segment IDs and validate owned source/time bounds and phase-1 limits. Editing the draft invalidates client approvals.

## Concurrency, idempotency and cost limits

At most 8 ready owned sources / 600 seconds, 24 JPEGs / 3MiB, compact prompt 96KiB, response 2MiB / 8192 output tokens (32768 for the planning and instruction-edit calls, which return up to 20 Thai items with effect fields; set per call via `editorai.WithMaxOutputTokens`), 20,000 transcript tokens, target 1–120 seconds. Phase-1 timeline remains at most 20 segments / 1200 seconds. Normal cold analysis with speech uses 3 calls (source-only transcript refinement + visuals + concepts), followed by 1 planning call. All-silent analysis skips refinement. Every HTTP attempt, including 429/timeouts/unknown responses, reserves a persisted call before sending; hard maximum 6. There is no automatic HTTP retry. Explicit retry honors retryAt, the remaining budget and at most 3 claims per phase. One queued/processing job per user, at most 5 unfinished per project and 20 new jobs per UTC day. User row locks serialize quota checks and a partial unique index protects active jobs.

Creation replay is checked before revision/quota/provider checks. Selection freezes the first concept and exact duplicates cannot trigger another call. Retry request IDs are retained across attempts. Apply checks both draft and project revision and the complete, duplicate-free approval set in a project→job transaction. Exact request replay returns the original applied project metadata/segments/revision, signed URLs freshly generated; a new request ID cannot apply the job twice. Snapshots/cache never persist signed URLs/base64 images. Every worker stage, cache publication and budget mutation requires the active claim token. Expired leases become failed; they are never automatically requeued to make another paid call. DB cancellation is observed by other workers within a bounded polling interval, cancelling subprocess/HTTP contexts. An already sent cloud request may still count toward provider usage.

Source caches are owner/asset/content hash/kind/model-version/options scoped and contain only validated transcripts or source-only visual descriptions. Brief-dependent concepts/plans are never source-only cached. Operator-provided Gemini/Whisper version values must change when deploying different model/prompt/runtime generations.

Worker failures not covered by a specific code keep `AI_PROVIDER_UNAVAILABLE` but carry a specific Thai `failureMessage` for: configuration changed since the job was created (model/ASR signature mismatch), analysis/ASR unavailable, source download failure (storage), and cancellation/timeout. Every worker failure is logged server-side as `video_editor_ai: job=… phase=… stage=… failed code=… err=…` (error sentinels only), plus a `source asset=…` line naming the download step that failed (signed URL, network, HTTP status or content hash).

409: `AI_BUSY`, `AI_SELECTION_CONFLICT`, `AI_DRAFT_CONFLICT`, `AI_ALREADY_APPLIED`, `AI_RETRY_NOT_READY`, plus phase-1 revision/idempotency conflicts. 429: `AI_DAILY_LIMIT`; a provider quota failure is persisted as `AI_RATE_LIMITED` with retryAt. 422: `AI_INPUT_TOO_LARGE`, `AI_INVALID_RESULT`; historical jobs may retain `AI_DURATION_MISMATCH` or `AI_INSUFFICIENT_EVIDENCE`. 503: `AI_UNAVAILABLE`, `ASR_UNAVAILABLE`; worker provider failures use `AI_PROVIDER_UNAVAILABLE`. Raw provider errors, API keys, transcripts/prompts and storage paths are not returned in errors/logs.

## Transcript refinement

After local ASR, raw transcripts are persisted while `stage:transcribing` remains active. A source-only Gemini call conservatively improves punctuation, spacing and unambiguous ASR wording before visual analysis, concepts or planning. The refined transcripts are persisted before the stage changes to `visual_analysis`, so polling can display them immediately without waiting for concepts. No database stage or column is added.

Each speech transcript may add `refinement:{text,segments:[{segmentIndex,text,uncertain}]}`. Original `text`, speech segments, words and all timestamps stay unchanged. The server validates one unique zero-based index per original speech segment, orders the results, and constructs `refinement.text`. Uncertain segments always retain the entire original segment text, even when the model suggests a replacement. The interpretation is not verified audio and does not modify the audio. The existing provider signature remains compatible; the separate refinement-v1 cache namespace versions this new step without invalidating existing planning jobs. Existing jobs omit refinement and continue to display/use raw speech.

Concepts use refined text when present. Planning receives source-level refined transcript context in every audio/silence mode. Speech evidence uses refined segment interpretation, preserving original speech/word boundaries; split-window descriptions explicitly identify the text as full-segment context rather than word-level alignment. Source-only refinements are cached under existing kind `asr` with a separate `refinement:` signature derived from both ASR and provider generations, never overwriting raw ASR records. Source/owner/content scoping and claim/cancel fences remain enforced. Invalid or oversized refinement fails explicitly through existing errors; it does not invent a fallback result, bypass the 6-call limit, or automatically regenerate. This extra call can add latency and provider usage; actual semantic quality requires evaluation with real Thai footage, not the isolated fixture.

## Target duration and nonblocking notices

`job.targetDuration` remains the user's requested target; each concept's `duration` is its planned estimate, and `draft.duration` is computed from actual selected windows. Concepts and drafts optionally include `durationReason` (Thai string; empty/omitted when reaching 95 percent of target). Existing jobs without this field remain valid. A model's unexplained short concept estimate is raised toward the requested target, capped by unique candidate coverage; an explicit shorter story with a reason remains selectable. Prompts receive candidate durations and aim for the full target rather than dividing the duration among concepts.

For shorter results, the server distinguishes limited prepared candidate coverage from a model-selected shorter interpretation. The fallback does not assert that all original source content is insufficient. Generated drafts report the actual duration and explanation; manual saves recalculate the notice and clear stale reasons when reaching target. A shortfall never creates a failed status, automatic provider retry, new paid call, or a minimum-duration approval/apply gate. Users may accept the shorter result, manually edit it, or start a new analysis. Existing job evidence and histories are not regenerated automatically. No database column or migration is required because the optional notice lives in the existing concept/draft JSON.


## Editorial pacing and pause-cache generation

Concepts and planning use source-supported opening, development, key point and ending as editorial roles. Roughly 3–6 units for 60 seconds is a soft guide, never a minimum-count failure or a fixed shot duration. A justified long shot remains valid when a useful change is not supported. Prompts no longer prefer the longest candidate or the fewest runs; they ask for meaningful selects, preservation of necessary context, and no invented visual angles or B-roll. Existing duration notices, target ceilings and nonblocking shorter approval remain unchanged.

Typhoon retains its stored provider `Signature()` for queued/planning compatibility and exposes a separate `CacheSignature()` with `pause-segments-v2`. Raw ASR and derived refinement caches use this separate identity. New analyses do not reuse old coarse-context or v1 ASR/refinements, while completed job transcripts and legacy planning remain unchanged. Other transcribers keep their existing cache signature. No migration, provider call or automatic regeneration is triggered by this cache separation.

## Automatic highlight composition

`autoCompose` is an optional boolean on creation, omitted/false preserves the
existing concept selection and segment approval flow. New clients may default it
to true only when capabilities advertise `autoCompose:true`. The frozen input
stores this choice, ready owned project audio sources and the presence/count of
manual tracks; no audio URL or arbitrary external source is accepted. Analysis
ranks source-grounded alternatives and atomically queues planning for the first
recommended concept. It does not pause at `awaiting_concept`. Planning still uses
only server evidence IDs; the provider schema never accepts arbitrary timestamps,
paths, caption timing or music URLs. The same cloud budget and claim fences apply.

The server expands a valid cut plan into `draft.textLayers`, `draft.audioClips`
and Thai `draft.compositionNotes`. The first two use the phase-one track shapes,
including optional `originJobId` UUID metadata. These draft fields are optional on the wire: empty arrays/notes are omitted,
including legacy jobs without composition. Clients normalize omitted fields to `[]`. Text combines short
plan-derived source-grounded opening/keypoint titles and original ASR captions.
A coarse ASR segment is captioned only when its entire timed span lies inside the
cut; partial segments require wholly contained timestamped words. Caption words
are grouped into short windows and mapped from source time to concatenated edit
time. Full context or refined interpretation is never assigned to an unsupported
shorter window. Segments containing zero-duration tokens use the original whole-segment text
only when fully contained; they are not partially captioned or stripped of Thai characters. Long coarse text without safe
subdivision is omitted with an honest no-caption note when none remain. Layer
text uses at most six short lines, with the existing 500-character and 50-layer
limits; room is reserved for frozen manual text layers.

Original audio follows `audioMode` (default client choice `keep`). If an owned
ready audio asset exists and there is no manual audio, its first bounded source
range is used as a quiet 12% bed; a short asset is not repeated. This does not
classify an uploaded file as music or synthesize speech. Without such an asset,
only original sound remains and the draft explains the absence of a background
bed. Existing manual audio suppresses the bed. There is no generated voiceover,
TTS or music-provider call. Subtitles still require renderer text capability to
export; a missing drawtext/font capability is reported by the existing editor.

Draft reorder/trim/delete regenerates composition against the frozen sources and
original transcripts without a cloud call. Apply keeps the existing explicit
`approvedSegmentIds`, revision guard, draft revision and idempotency contract;
clients may approve the entire automatic edit in one action. In one transaction,
apply replaces video segments and prior tracks explicitly marked with a valid
`originJobId`, preserving every unmarked manual track. Current manual audio also
suppresses a generated bed even if added after analysis. Current project audio
ownership/ready/source bounds, text validity, timeline bounds and merged counts
are validated before apply; overflow fails instead of deleting manual layers.
Manual-save normalization accepts only omitted or valid UUID origin metadata.
Legacy/manual-mode jobs continue replacing segments alone. No migration or
regeneration of existing jobs is required.

## AI editing tools

Draft segments carry the same optional effect fields, with the same JSON names and meaning, as phase-1 timeline segments: `speed`, `fadeIn`, `fadeOut`, `transition`, `transitionDuration`, `brightness`, `contrast`, `saturation`, `fit`, `zoom`, `panX`, `panY`, `zoomTo`. Omitted or zero means unchanged. The planning schema lets the model choose them per selected window from the editor's own ranges and enums (transitions `fade|fadeblack|fadewhite|wipeleft|wiperight|slideleft|slideright|circleopen`, 0.1–2 s and at most half of both neighbouring played lengths, never on the first segment; speed 0.25–4; fades 0–10 s within the played length; look −1..1, zoom 1–3, fit `cover`). Provider schemas (all calls) use only the Gemini structured-output keywords `type`, `properties`, `required`, `items`, `enum`, `minimum`, `maximum`, `minItems`, `maxItems` and `description` (no `pattern`/`format`; enforced by `TestAISchemasUseSupportedKeywords`); colour format is described, not pattern-constrained, and validated server-side. Speed 1 and zoom 1 are stored as 0 (unchanged). The server re-checks every value with the manual editor validators (`veValidSpeed`, `veValidFades`, `veValidTransition`, `veValidLook`) in timeline order; an invalid value is reset to unchanged and never fails the draft. The model may also return optional `captionStyle`/`titleStyle` (`color`, `outlineColor`+`outlineWidth`, `boxColor`+`boxOpacity`, `animation fade|slide`, `y`, `fontSize`); an `outlineColor` without width gets width 3 and a `boxColor` without opacity gets 0.6 (the edit tool defaults); each group is kept only if `normalizeVETextLayers` accepts it, and the result is persisted as additive `draft.textStyles` so that composition regenerated after a manual draft edit keeps the same look. Composed text layers keep the phase-1 `TextLayer` shape.

`draft.duration` is the timeline length after speed and transition overlap (the same total the export validates). Selected windows still fit the target at 1×; for generated drafts, slow motion (`speed < 1`) is removed if it would push the timeline past `targetDuration + 0.05`, so the generated target rule always holds. Faster speeds and transitions only shorten the result and may produce the existing nonblocking shorter-duration notice. Captions and titles are mapped to edit time using each segment's speed and transition start. Exactly adjacent windows are merged only when speed and look match and no fade or transition would land inside the merged span.

`PUT /ai-jobs/:id/draft` accepts the effect fields and returns the normalized draft (invalid effects reset to unchanged, as above). Manual draft edits may exceed the target like other manual edits (1200 s cap). `evidenceId` is server-owned: the stored value for each known segment is kept regardless of what the client sends. `POST /ai-jobs/:id/apply` copies every effect onto the timeline segments, after validating the exact stored segments with the phase-1 segment validator against the project's current assets (`422 VALIDATION_ERROR` if they no longer pass).

## Instruction edits

`POST /projects/:id/ai-edits/preview` body `{instruction: string, revision: int}`. The instruction is trimmed and must be 1–500 runes of valid UTF-8; `revision >= 1`. Response `200 {data:{baseRevision, summary, operations:[{tool,target,description}], proposal:{title,aspectRatio,segments,audioClips,textLayers,imageLayers}}}`. `proposal` is exactly the body to send to the existing `PUT /projects/:id` with `revision = baseRevision`; the preview never saves. `imageLayers` is omitted only when migration 028 (image layers) is absent, because PUT would reject the field; image tools are then unavailable. `summary` and `description` are model-written Thai, stripped of control/bidi characters and bounded to 500/200 runes; a missing description uses a short Thai default per tool. When operations were skipped the summary ends with `(ข้ามคำสั่งที่ใช้ไม่ได้ N รายการ)`. `operations` lists only applied operations, in order; `target` is the affected ID (the new ID for `add_text`/`add_image_layer`).

The model returns at most 20 tool calls via a strict JSON schema: `set_segment` (speed, volume, fadeIn, fadeOut, transition — `none` removes, transitionDuration, brightness, contrast, saturation, fit `cover|contain`, zoom, panX, panY), `trim_segment` (start/end source seconds), `move_segment` (zero-based `index`), `delete_segment`, `add_text`/`update_text` (TextLayer fields; animation `none` removes), `delete_text`, `add_image_layer` (`assetId` of a ready project image asset) / `update_image_layer` / `delete_image_layer`, `update_audio_clip` (volume, fadeIn, fadeOut). The server applies each call in memory to a copy of the stored timeline and keeps it only if the whole timeline then passes the same validators as PUT (`validateVESegments`, `validateVEAudioClips`, `normalizeVETextLayers`, `validateVEImageLayers`). Unknown tools or IDs, fractional integers and invalid values reject that call only. A field the tool does not accept is ignored when it would change nothing (absent/null, `0`, `""`, `"none"`, or equal to the target's current value, e.g. a segment's current `index`); if it would change something the call is rejected. A call whose accepted fields are all absent is rejected. Speed 1 and zoom 1 are stored as 0. Moving or deleting a segment clears a transition left on the new first segment. Instruction, asset names and text-layer contents are sent as untrusted data (text excerpts bounded to 120 runes); no transcripts or media are sent.

Before any quota or provider use, the stored timeline is checked with the same PUT validators; if it already fails (e.g. legacy data), the preview returns `422 AI_EDIT_BASE_INVALID` ("ไทม์ไลน์ที่บันทึกไว้ไม่ผ่านการตรวจสอบ กรุณาแก้ไขและบันทึกโปรเจกต์ก่อนใช้ AI แก้ไข") rather than `AI_EDIT_NO_CHANGES`.

Errors: `404 NOT_FOUND` (project missing or another user's), `409 REVISION_CONFLICT` when `revision` differs from the stored project, `400 VALIDATION_ERROR` for a malformed body or instruction/revision out of range, `422 AI_EDIT_BASE_INVALID` when the stored timeline itself fails PUT validation, `422 AI_EDIT_NO_CHANGES` when no valid change remains (including calls that leave the timeline identical), `422 AI_INVALID_RESULT` for a schema-violating model response, `422 AI_INPUT_TOO_LARGE` when the prompt exceeds 96 KiB, `503 AI_UNAVAILABLE` when AI is disabled, the provider is not configured or editor media is unavailable, `503 MEDIA_UNAVAILABLE` before migration 024, `503 AI_PROVIDER_UNAVAILABLE` for a provider/network failure or timeout, `429 AI_RATE_LIMITED` for provider quota or while the same user already has a preview in flight, and `429 AI_DAILY_LIMIT` after 50 previews per user per UTC day. Provider errors are never forwarded. The call is synchronous with a 60-second bounded provider timeout, makes exactly one provider call per accepted preview, and persists nothing. Quota: one preview per user in flight is admitted first; the daily count is charged only after body, availability, project/revision, base-timeline and 96 KiB prompt-size checks pass, immediately before the provider call. Provider failures and timeouts are not refunded, because the request may already have reached (and been billed by) the provider. The per-user limiter is in process memory (no migration): limits reset on restart and are per API instance. `capabilities.instructionEdits` is true when AI is enabled, the analysis provider is configured and the editor media stack is available; it does not require ASR or the AI job tables. Clients should show the existing `cloudNotice` before sending, since the timeline description is sent to the same provider.

## Captions from word-less transcripts

Typhoon (and any transcript without valid word times) yields pause-derived segments of up to 12 s. A segment fully inside a cut is now split into captions of at most 48 runes and two lines, breaking only between words: Thai words are found by dictionary maximal matching (`apps/services/thaiseg`, PyThaiNLP `words_th.txt`, CC0-1.0, embedded), and only a single word too long for a caption is cut, at syllable-safe points (never before a combining mark or ะ า ำ ๅ, never after เ แ โ ใ ไ). Every caption and title line wraps the same way (24 visible columns, combining marks take none). Times are ESTIMATED by spreading the segment's duration in proportion to each piece's length. Previously such segments became one long caption or were dropped above 144 runes. Captions stay inside their clip's own part of the timeline — after the transition from the previous clip and before the transition into the next — and are dropped when shorter than 0.3 s after that clamp, so a caption never runs into another clip (story composition and chat `add_subtitles`; titles are unchanged). A segment that a cut crosses is not captioned from its transcript text (no alignment says which words are inside). Instead the part of the audio inside the cut (≥ 0.6 s) is extracted with ffmpeg and transcribed again on its own by the configured local ASR, so its text was spoken inside the cut; it is then split and timed like any word-less segment (estimated within that part). Up to 12 parts / 300 s per story-job composition (adds a Thai `compositionNotes` entry) and 6 per chat `add_subtitles`, batched 8 per ASR call with throwaway UUIDs. Best effort: missing ASR, download, ffmpeg or ASR failure leaves that part uncaptioned and never fails the plan. Local ASR only — no cloud cost. Applies to story-job composition and chat `add_subtitles`.

Chat `set_story` / `add_segment` move a cut end that falls inside a speech segment of the clip's stored transcript to that segment's nearer boundary when it is within 0.5 s (not applied if the cut would become shorter than 0.3 s); the operation description says how many ends moved. Story-job plans already cut on server evidence boundaries.

## AI chat editor (experimental)

A chat thread per project in which the model works through tools: it reads the project and the clip analysis of earlier story jobs, edits a private copy of the timeline, or starts the existing story job. Each reply produces at most one **proposal** (the net timeline change) that the user applies or discards; the model never saves the project. Web: the "แชท" tab of `/studio/ai-editor`, shown only when the web build sets `NEXT_PUBLIC_AI_CHAT_EDITOR=true`.

Setup: `EDITOR_AI_CHAT_ENABLED=true` (default false), `EDITOR_AI_ENABLED=true` with the editor media stack available, and migration `031_video_editor_ai_chat.sql` (table `video_editor_ai_chat_messages`, after 022). Provider `EDITOR_AI_CHAT_PROVIDER=gemini` (default; `GEMINI_API_KEY`/`GEMINI_MODEL`) or `claude` (`ANTHROPIC_API_KEY` and `CLAUDE_MODEL`, both required). Optional `EDITOR_AI_CHAT_MODELS=gemini:gemini-3.5-flash-lite,claude:claude-haiku-5-5,...` lists the models the user may pick per message (unknown providers and duplicates skipped; a model whose provider key is missing is listed with `available:false`). The configured provider is the default when it is listed and available, otherwise the first available listed model. Each stored reply records the provider/model it used, so `/ai-chat/usage` splits cost by model. Until all of these hold, `GET` answers `available:false` with a Thai `unavailableReason` and every other editor feature keeps working.

Routes (under `/open/v1/video-editor/projects/:id/ai-chat`, owner only; non-UUID `:id`/`:mid` → 404; body > 64 KiB → 400):

Usage (hidden web page `/studio/ai-usage`, not in the navigation): `GET /open/v1/video-editor/ai-chat/usage?days=1..365` (default 30) → 200 `{days, since (Asia/Bangkok date), priceSource, unpricedModel, total, models:[{provider, model, inputPricePerMTok, outputPricePerMTok, ...totals}], byDay:[{day, ...totals}], projects:[{projectId, title, ...totals}]}` where totals = `{replies, steps, inputTokens, outputTokens, costUsd|null}`. Only the caller's own assistant replies; cleared (soft-deleted) messages and deleted projects are included because their tokens were billed. `costUsd` = tokens × list price per 1M from the table in `video_editor_ai_chat_usage.go` (longest model-id prefix match); null when any model in the bucket has no price. Estimates ignore free tiers, cache/batch discounts and Haiku 5.5's >100K-prompt rate. Gemini output includes `thoughtsTokenCount` (billed as output) from 2026-11-10. Analysis jobs and instruction edits are not counted (their usage is not stored).

Message: `{id, role: user|assistant, content, createdAt, tools:[{name,label,ok}], proposal?, jobId?, error?}`. Proposal: `{baseRevision, summary, operations:[{tool,target,description}], proposal:{title,aspectRatio,segments,audioClips,textLayers,imageLayers?}, status: pending|applied|discarded|stale, appliedRevision?}`. `error` is a machine code stored with a reply that stopped early (`AI_TIMEOUT`, `AI_RATE_LIMITED`, `AI_DAILY_LIMIT`, `AI_INVALID_RESULT`, `AI_INPUT_TOO_LARGE`, `AI_PROVIDER_UNAVAILABLE`); clients show a Thai hint, not the code.

Stream: the request is validated before streaming, so body/consent/availability/ownership failures are ordinary JSON errors. Once streaming, frames are `event: <type>\ndata: <json>\n\n` with `{type:"status", tool, label}` while tools run (first frame `tool:"thinking"`), then exactly one `{type:"message", message}` (the stored assistant reply) or `{type:"error", code, text}` (`AI_CHAT_BUSY`, `AI_DAILY_LIMIT`, `AI_CHAT_FAILED`). The user message is stored before the model runs and the reply is stored even if the client disconnects, so a reload shows it. The web proxy passes this route through unbuffered.

Tools the model may call: `get_project`, `get_clip_analysis`, `find_moments` (keyword search over stored transcripts/frame descriptions), `look_at` (1–4 frames of a ready video, at most 2 calls per reply), `start_story` (creates the existing auto-compose AI job; one per reply, and no timeline edits after it in that reply), `set_story`, `add_segment`, `add_audio`, `add_subtitles` (captions from stored transcripts — the ASR text of earlier story jobs, Whisper or Typhoon depending on which ran — then proofread by the model the user picked for this message: one extra call, charged to the daily cap and counted in the reply's usage/steps; a caption is replaced only when the model marks it certain and its length stays within 0.5×–1.5× (+6 runes) of the original, otherwise the transcript text stays; reruns replace its own captions), `edit_timeline` (the operations of [Instruction edits](#instruction-edits), same per-call rejection rules). Every change is kept only if the whole timeline passes the PUT validators. If the stored timeline already fails them, editing tools return an error and read tools still work.

Limits: one reply in flight per user (`429 AI_CHAT_BUSY`), at most 8 model calls per reply and 6 tool calls per model call, 140-second reply timeout, 300 model calls per user per UTC day (in process memory, per API instance, reset on restart), last 16 messages replayed as plain text plus a fresh project state. Tool arguments and results are not stored; only the tool trail (name, label, ok) and token usage are kept in the message meta.

Errors: `400 VALIDATION_ERROR`, `422 AI_CONSENT_REQUIRED` (cloudConsent false), `404 NOT_FOUND`, `409 AI_PROPOSAL_NOT_PENDING` (apply/discard of a proposal that is not pending), `409 REVISION_CONFLICT` (project changed after the proposal; the proposal becomes `stale`), `429 AI_CHAT_BUSY`, `503 AI_UNAVAILABLE`. Apply and discard use a compare-and-swap on the message meta; if a discard from another tab lands while an apply is saving, the saved project wins and the message is recorded as `applied`.

Data sent to the provider (shown to the user as `cloudNotice`): the messages, asset names, the timeline, stored transcripts and frame descriptions, and frames requested by `look_at`. All of it is marked as untrusted data in the prompt.

## Chat tool: reframe (2026-11-10)

`reframe {segmentIds?, subject?, framing: tight|medium|wide}` extracts the middle frame (≤640 px) of up to 8 segments, asks the user's chosen chat model in one call (counted against the daily cap and added to the reply's usage) for a 0–1 subject box per frame, then sets `fit: cover`, `zoom` and `panX/panY` so the subject sits in the project's aspect: zoom = min(fill·visibleHeight/boxHeight, 0.95·visibleWidth/boxWidth) clamped 1..2.5 (fill 0.75 tight, 0.55 medium, none for wide), pan centres the box (aimed at 45% of its height). Segments where the subject is not found stay unchanged. The result is part of the reply's proposal like any other edit.
